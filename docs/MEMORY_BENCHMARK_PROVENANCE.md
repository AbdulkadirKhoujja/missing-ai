# External memory benchmarks: provenance record (LoCoMo, LongMemEval, BEAM)

**Status: provenance notes only. MissingAI has not been run on any of these benchmarks. This document contains no MissingAI score, and none may be added here or anywhere else in this repository until the gates at the end of this document are met.**

Roadmap [#86](https://github.com/AbdulkadirKhoujja/missing-ai/issues/86), Gate D. Checked on 16 November 2026 by an automated development run, by reading the upstream pages listed under each benchmark. Nothing was downloaded: no dataset file, no evaluation script.

## How to read this record

Each fact below is in one of two states.

- **Confirmed** means the fact was read on the named upstream page on the check date.
- **Not confirmed** means the page that would settle it could not be read in this run. It does not mean the fact is false. It means nobody on this project has verified it yet, and it must be verified before any use.

The three upstream code repositories on GitHub could not be read in this run. Everything that only those repositories can settle — code licence, data file names, evaluation script names, whether scoring needs a paid model API key — is therefore **not confirmed** for all three benchmarks. The licence of a paper on arXiv is not the licence of its dataset or code and is not used as a substitute here.

Upstream result figures are deliberately not reproduced. They describe other systems, and a number printed in this repository is easily misread as ours.

## What these benchmarks measure, and what they do not

All three are question-answering benchmarks over long conversation histories: a system reads or stores a long history, is asked a question, and its answer is scored against a reference.

MissingAI's core claim is different: given a source and a draft, report source-backed omissions and contradictions with exact quotations. None of the three benchmarks carries omission labels for that task. So:

- A native result on any of them would be a **question-answering** result under that benchmark's own protocol. It would not be omission-detection precision or recall, and must never be presented as such.
- Omission-detection precision and recall on these datasets are **N/A** unless a separately reviewed labelling protocol exists. Benchmark labels and scoring are REVIEW-class under [the open-source boundaries policy](OPEN_SOURCE_BOUNDARIES.md).
- The closest native overlaps are the abstention and contradiction abilities noted below. They are related to, not the same as, MissingAI's abstention and contradiction findings.

Relevance to MissingAI: BEAM is the only one of the three with a named contradiction ability and a named abstention ability. Its scoring is judge-based nugget credit on answers, which is still not omission-detection precision or recall.

## Gates before any MissingAI number on these benchmarks is published

These restate the roadmap and the open-source boundaries policy; they add no new authority.

1. The benchmark's licence has been confirmed from its own licence file and permits the intended use. No dataset content is committed to this repository unless the licence clearly allows redistribution and the maintainer approves it.
2. The run uses the upstream data unmodified and the upstream scoring protocol, including the judge model the authors specify where the protocol depends on one. Any deviation is stated next to the number.
3. The run is reproducible from a recorded commit, dataset revision, command and configuration, and was actually executed. A planned, partial or estimated run produces no number.
4. The result is labelled with the benchmark's native metric name. It is not relabelled as omission detection, accuracy of MissingAI in general, or real-world reliability.
5. The maintainer has reviewed the method and the wording before publication.
