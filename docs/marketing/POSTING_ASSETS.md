## DEV / Hashnode educational piece (canonical to original guide)

**Recommended title:** How I Check Whether an AI Answer Actually Covered the Brief

**Original reference:** https://abdulkadirkhoujja.github.io/missing-ai/guides/how-to-check-ai-answer.html

**Platform note:** Use DEV's `canonical_url` only when syndicating an already-published, substantially identical article. A new unique post should not falsely designate a different page as its canonical. Do not automate cross-posts without an account and rules review.

> A confident AI response isn't an acceptance test. If you asked for webhook signature verification, booking cancellations and receipts, a response that mentions the first two while acknowledging receipts weren't implemented is not a complete delivery—even if the writing sounds excellent.
>
> I review the original instructions line by line and separate: (1) what is explicitly claimed, (2) what isn't clearly mentioned, (3) what is explicitly contradicted, and (4) what I cannot determine. The last category matters when the answer is ambiguous.
>
> A wording-based checker can find obvious gaps, but it can also generate false alarms. For example, "withdraw a reservation" may refer to cancelling a booking, and one shared keyword doesn't guarantee a requirement has been met.
>
> The second check must preserve the source instructions and the AI answer quotations. The next step is to inspect implementation evidence separately: repository changes, acceptance tests or real observed behaviour.
>
> I built Missing AI to help make this review reproducible. The open-source browser version runs local pasted-text checks. A controlled-beta MCP workflow can help ChatGPT or Claude reason about selected public requirements, but the host model can still be wrong.
>
