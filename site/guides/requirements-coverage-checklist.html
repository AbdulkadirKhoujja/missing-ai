Requirements Coverage Checklist for AI Coding Assistants

Coding assistants can generate convincing progress summaries. A requirements coverage review is a practical way to identify which acceptance criteria the summary addresses—but it is not a substitute for running the code.

Map requirements to claims

Keep the original feature request, issue or acceptance tests. List the must-have behavior, failure cases, security requirements, data constraints, and user journeys. For each, identify the exact statement the assistant makes about completion. “Implemented validation” is too vague if the brief requires verifying a specific signature.

Look beyond the happy path

Payment examples may involve signature verification, idempotency, expired sessions and receipt delivery. Booking examples may require capacity limits, cancellation windows and duplicate prevention. An assistant mentioning the core feature does not establish all these separate obligations.

Separate three kinds of evidence

Answer claim: “I added cancellation support.” Repository evidence: a specific source change and test reference. Observed behavior: a failing or passing test, reviewed logs or an end-to-end user action. Missing AI checks the first category, and requires separate inspection for the other two.

Use Missing AI without overstating it

The free web checker highlights wording discrepancies in a pasted brief and assistant summary. Through a custom ChatGPT/Claude MCP beta, the host can propose semantic coverage and duplicate groups across selected public source pages; Missing AI checks answer quote offsets and whether each extracted source reference was included. It does not run GitHub tests or certify deployed software.

Build a useful handover

For each not-clearly-covered item, request the implementation location, a relevant test name and evidence of the claimed outcome. Keep unresolved conditions visible until the repository and real application have been checked.

Example: webhook signatures

Criterion: Reject Stripe webhook events with invalid signatures.

Assistant: “Stripe events are checked using the signing secret.”

Coverage verdict: Signature checking is claimed. The answer alone cannot establish that invalid signatures are rejected. Inspect the verification call, failure branch and signed-webhook test.
